# Issue #122 — Better Print/PDF: single-page briefing

_Drafted 2026-05-17. Source: [#122](https://github.com/jloosli/mountain-worksheet/issues/122)._

## Problem

Printing the worksheet today produces several pages of cluttered output. The current `@media print` rules in `src/app/globals.css:43-78` strip colors and un-stick chrome but also force-render the closed Instructions and Checklist slide-overs as appendices, so the printed artifact balloons into multiple pages even though pilots want a single 8.5×11 briefing they can fold into a kneeboard.

The `ActionBar` already shows a `Print briefing` button in the `all-done` state (`src/components/ActionBar.tsx:132-138`) but it has no `onClick` — it's inert.

## Goal

A pilot can print a one-page 8.5×11 (US letter, portrait) briefing of the sortie at any time. The briefing carries all data that influences the go/no-go decision and nothing else.

## Non-goals

- A separate "Sortie Files" multi-page artifact with Instructions and Checklist appendices. The previously-planned multi-page print direction (Phase 5 of the UI redesign series) is superseded.
- A Go/No-Go summary panel. That is recommendation #1 from `docs/ux-assessment.md` and tracked separately.
- A PDF export pipeline (server-side or `@react-pdf/renderer`). `window.print()` to the browser print dialog is sufficient; the browser's "Save as PDF" satisfies the PDF case.
- Signature/sign-off lines. Out of scope for v1; can be added later if pilots ask.

## Approach

Add a dedicated `<PrintBriefing>` component, rendered inline at the bottom of `AppContainer`. The briefing is `hidden print:block`; the rest of the app receives `print:hidden` so only the briefing prints. The existing `Print briefing` button in `ActionBar` is wired to call `window.print()`.

Trade-offs considered:

- **A — Aggressive `@media print` rewrite of the existing DOM.** Single source of truth, no new component. Rejected: the current tree was built for screen, with tall sections, large headings, and structural padding. Wrestling it into 8.5×11 across Chrome/Safari/Firefox print engines is brittle and constrains future screen-side changes.
- **B — Separate `/print` route.** Full layout control. Rejected: duplicate render of derived state, awkward "Print" trigger (new tab vs same tab), URL state needs to be passed through, and we lose the screen → print round-trip via the browser's print dialog.
- **C — Inline `<PrintBriefing>`, `hidden print:block` (chosen).** Same data, parallel DOM only visible when printing. Tight layout control without leaving the page; the same React state and derived helpers (`computePressureColumns`, `computeTOLDViewModel`, `calculateManeuveringSpeeds`) feed both. Slightly heavier DOM is an acceptable cost.

The current `@media print` block that force-shows closed slide-overs is removed.

## What prints (top to bottom)

The briefing fits a US letter portrait page at ~0.4in margins, 9–10pt base font, monochrome with minimal accent colors.

1. **Title strip** — "CAP Mountain Flying Worksheet — Briefing" left, generated-at UTC timestamp right.
2. **Identity line** — Pilot · AC Model / Tail # · Date (UTC) · Time (UTC) · Duration · Mtn Endorse ✓/✗ · Mtn Cert ✓/✗.
3. **Route line** — Departure → Arrival · Area of Ops / Route · Position (lat/lon).
4. **Conditions block** — Two columns:
   - **Winds aloft** compact table: rows = 3k / 6k / 9k / 12k / 15k; columns = Dir, Vel, Temp.
   - **Advisories**: AIRMET flags (Turb / CielVis / MtnObsc) rendered as labeled chips with ✓/✗ markers.
5. **Per-phase environment** — 3-column table: Departure / Operating / Arrival; rows = Actual Altitude (matching the `Altitudes` table's label), OAT, Altimeter, Pressure Alt, Density Alt.
6. **Takeoff & landing distances** — Same shape as `TakeoffPerformance` on screen, but compact: rows = TO Ground Roll, TO over 50' obstacle, Landing Ground Roll, Landing over 50' obstacle, Available runway remaining; columns per airport. Negative runway remaining keeps its red tint (with `print-color-adjust: exact` so the cue survives print).
7. **Rates of climb & V-speeds** — From `ClimbPerformance`: ROC (MGW + actual weight), Vx, Vy, Va, Vra, Percent MGW, Service Ceiling.
8. **Maneuvering / canyon turn speeds** — From `ManeuveringPerformance`: flap settings × bank angles (0° / 45° / 60°).
9. **Footer band** — "For reference only — PIC and FRO are responsible for the go/no-go decision." + small "Generated by mountain-worksheet.vercel.app" line.

Missing values render as `—`. If aircraft is not selected, sections 5–8 collapse to a single "Aircraft model required" line so identity + route + conditions still print usefully.

## Components and changes

**Create:**

- `src/components/PrintBriefing.tsx` — pure render of the briefing from `WorksheetData`. Receives `state: WorksheetData` and computes its own derived values via the same helpers `Calculations.tsx` calls — `computePressureColumns`, `computeTOLDViewModel`, and `calculateManeuveringSpeeds` — so there is no duplicated calculation logic. The component is unconditionally rendered in the React tree but visually `hidden print:block`. Internal layout uses absolute units (`pt`, `in`) and a CSS grid; it does not rely on the surrounding Tailwind design system beyond a thin set of utility classes.
- `src/components/PrintBriefing.test.tsx` — fixtures cover: fully-populated sortie renders all sections; missing values render as `—`; no aircraft selected hides performance sections; negative runway-remaining cells retain the red class.

**Modify:**

- `src/components/ActionBar.tsx` — move the existing `Print briefing` button out of the `all-done`-only branch into the persistent right-side cluster next to `Checklist`. Add an `onPrint: () => void` prop and wire the button's `onClick`. Button is enabled regardless of state.
- `src/components/ActionBar.test.tsx` — assert the Print button renders in every state (`incomplete`, `ready`, `fetched`, `all-done`) and calls `onPrint` when clicked.
- `src/components/AppContainer.tsx` — add an `onPrint` handler that calls `window.print()`, pass it through to `ActionBar`, and mount `<PrintBriefing state={state} />` inside the top-level wrapper. Add `print:hidden` to `<WorksheetHeader>`, `<Stepper>`, the `ActionBar` wrapper, `<main>`, the two `<SlideOver>` mounts, and the `<footer>` so only `<PrintBriefing>` survives the print pass.
- `src/components/AppContainer.test.tsx` — assert clicking the print button calls `window.print()` (jest-mocked); assert `<PrintBriefing>` is rendered.
- `src/app/globals.css` — remove the lines 50–77 block that un-sticks chrome and force-renders closed slide-overs. Replace with a minimal print block: `@page { size: letter; margin: 0.4in; }`, force white background + black text, suppress shadows and animations, and the two `print-color-adjust: exact` declarations needed by the red/amber cues. All other layout rules live inside `PrintBriefing.tsx` via Tailwind `print:` utilities.

**No deletes.** The `SlideOver` print-mode class names that were added in Phase 5 (`print:static`, `print:break-before-page`, etc.) become dead code; they don't cause harm because the slide-overs are now hidden in print and can be cleaned up in a follow-up.

## Data flow

`PrintBriefing` is a pure render component. It re-runs the same derivations as `Calculations` from props each render — table lookups are sub-millisecond per the existing architecture note in `AGENTS.md`, so this is cheap. No new shared cache is introduced.

```
WorksheetData (state in AppContainer)
       │
       ├─► Calculations          (screen path)
       │     ├─ computePressureColumns
       │     ├─ computeTOLDViewModel
       │     └─ calculateManeuveringSpeeds
       │
       └─► PrintBriefing         (print path)
             ├─ computePressureColumns
             ├─ computeTOLDViewModel
             └─ calculateManeuveringSpeeds
```

If the duplicated derivation calls feel like a smell during implementation, extract a thin `usePrintModel(state)` helper into `src/utils/derived.ts` — but not preemptively.

## Visual style

- Base font: 9pt sans (Geist / Helvetica / Arial via the existing `body` font-family).
- Tables: 8pt, 1px solid `#cbd5e1` borders, no shadow, `border-collapse: collapse`, `break-inside: avoid` per section.
- Color cues retained:
  - Negative runway-remaining: text in `#b91c1c` (red-700), preserved via `-webkit-print-color-adjust: exact; print-color-adjust: exact;` on the cell.
  - AIRMET flag ✓: text in `#b45309` (amber-700); ✗: muted gray.
- No emoji, no icon glyphs that depend on web fonts loaded asynchronously. Use plain Unicode `✓` / `✗`.

## Risks and mitigations

- **Browser print-engine drift.** Chrome / Safari / Firefox interpret `@page` and `print-color-adjust` consistently in recent versions, but font-rendering and table-collapse details vary. Mitigation: hand-test in all three before merging; if a layout breaks, prefer making `PrintBriefing` more conservative (drop a column, shrink font) over per-browser hacks.
- **Future calculation additions diverge between screen and print.** Mitigation: keep both code paths calling the same derivation helpers from `src/utils/derived.ts`. If a third caller appears, extract `usePrintModel`.
- **Worksheets with many runways / long airport codes overflow.** Mitigation: each section has `break-inside: avoid`, so worst case we get a second printed page rather than a torn table. The page-fit acceptance test covers the typical case.
- **The browser print dialog blocks the page.** Expected behaviour; no mitigation needed. Users who want a PDF use the dialog's "Save as PDF".

## Open questions (none blocking implementation)

1. Should the per-phase environment table show the user-entered field elevation, or the canonical airport elevation when known? Current screen behaviour shows user input; keep that for parity.
2. Long pilot names or aircraft tails — truncate or wrap? Default: wrap, since names are short in practice.
